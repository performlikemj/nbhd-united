**Status:** v2 — absorbs adversarial review round 1 (Fable-family critic, 2026-08-07: SOUND-WITH-CHANGES; 1 P0 + 4 P1 confirmed + 7 P2 folded in; arbitration recorded in §4). Implementation-ready for waves W1a–W1c. Author: Fable.
**Siblings:** `pii-coverage-audit-2026-08-04.md` (commissioning audit; §5C is this program) · `transcript-memory-postgres-directive.md` (provenance types + ciphertext pattern reused) · `encryption-at-rest-directive.md` (this program is the precondition for encrypting `Document`) · `ios-chat-redaction-transparency-directive.md` (the purple-affordance contract this extends to Layer-1).
**Prior phases:** #1376 egress guard (known-values, no NER — `apps/pii/egress.py:78-114`) + #1377 entity legend sealed model egress for KNOWN names. Phase 3 makes the stores themselves placeholder-space so unknown names stop existing downstream.

**One-line summary:** Every Layer-1 authoring write passes through ONE provenance-aware redaction chokepoint that stores placeholder-space text plus a per-field STATE-bearing receipt; owners get rehydration + entity metadata on every read surface; searches translate names to placeholder variants; entity retirement becomes registry-aware so rehydration can never be orphaned; per-tenant flag with pre-P3-preserving off semantics, canary-first; migration is designed here and run only on MJ's explicit go.

## 1. Product contract
1. The owner always sees their own real names — every owner-facing surface rehydrates (web, iOS, Telegram/LINE deliveries, Siri, dashboard). A surface that shows raw placeholders to the owner is a bug (today: Dashboard Horizons, owner memory view, journal-entry/review serializers).
2. The model and every cloud egress see placeholder-space only. Runtime/M2M reads never rehydrate. Third-party exceptions are enumerated (sautai prompt rehydration at egress — deliberate, `sautai_client.py:289-308`) — nothing else. **Siri today violates this twice** (`siri_views.py:87-110` rehydrated snapshot AND :199-204 raw spoken intent, both into a cloud-model request) — named fix W1a, standalone value.
3. Authoring never loses user data. The chokepoint is **fail-open-with-receipt** — a deliberate divergence from the transcript ledger's fail-closed gate, because these stores are the PRIMARY copy (the transcript ledger is a derived copy; refusing or blanking a journal save is data loss). On NER failure the chokepoint STILL applies the deterministic known-values scrub (`redact_known_values`, independent code path — narrows the leak to unknown values), stores the result with an `unconfirmed` receipt, enqueues repair, and alerts at >1% ERROR rate. Receipt reason codes are enumerated: `empty-input` and `redaction-disabled` are NOT errors (no repair row, no alert contribution); genuine `redaction-error` feeds both the sweep and live error-rate alarm, while intentional request-path `detector-deferred` feeds the hourly sweep but not error telemetry. Silent fail-open (today's `redact_user_message()` on owner edits) is the thing being retired.
4. Purple affordance parity is the product payoff: every Layer-1 field that can carry an entity emits chat-parity metadata (offset-free `{placeholder, value}` lists per `placeholder_redactions()`, `pending_queue.py:2572-2605`) so iOS renders the same tappable entity object everywhere. Backend contract only; iOS rides its own train.
5. Search keeps working for names: owner searches translate by generating QUERY VARIANTS — for each name binding whose value is a substring of the query, substitute to produce a placeholder variant; OR-union original + variants (`icontains` is whole-string substring matching — term tokenization would silently broaden semantics). All bindings via `inverted_names_multimap()` (winner-only `inverted_names_ci` drops same-name collisions). Search is recall-over-precision across collisions; the ASSISTANT-side refusal rule (transcript directive C10) still applies wherever an agent answers from results — including the Siri/Shortcuts disambiguation picker this endpoint feeds.

## 2. Architecture decisions

### A1 — ONE chokepoint, three writer classes, honest mint policy
New `apps/pii/authoring.py`: `author_text(tenant, text, *, seam, writer, ...) -> AuthoredText` (stored text + per-field receipt). Writer classes:
- **owner** (JWT/console/PAT): full NER + `MINT_ALL` — chat-ingress parity; the human is introducing names.
- **runtime** (M2M from the tenant container): model output, already placeholder-space; request-path writes synchronously scrub known values, perform no deep detector call, and persist `unconfirmed` / `detector-deferred` receipts for the hourly repair sweep. Repair retains `MINT_NEVER`; if it detects a model-composed name, it records `residual_spans` (count + kinds only, state `residual`) rather than minting. (Verified: no ordinary runtime write seam carries raw user text; user text reaches runtime endpoints only post-ingress-redaction.)
- **background** (extraction proposals, reconciliation evidence, reply artifacts, friends mission absorption): full detection + `MINT_VALIDATED` + always known-values scrub. Server-composed Document defaults reached during runtime requests preserve background provenance but use the same detector-deferred receipt path so first-touch writes cannot hang. The document-keep ingestion boundary is deliberately excluded from deferral: PDF/email filenames and excerpts bypass chat ingress and require synchronous validated detection before persistence. **Stated honestly (review P1-2): `MINT_VALIDATED` cannot mint PERSON/LOCATION by contract** (`_should_mint_new` → `hygiene.validate_structured`; `junk_sweep.py:59-64`). Unminted PERSON/LOCATION detections are therefore recorded in the receipt as `residual_spans` (count + kinds, never the values) and the field state is `residual`, NOT clean — the repair sweep and migration target `residual` fields; the >1% alert counts them separately from errors. v1.0 deliberately does not mint PERSON from LLM-derived text (junk-map growth); revisit with a high-confidence gate only if residual telemetry demands it.
NER cost: local synchronous DeBERTa CPU (~600MB singleton, `engine.py:60-103`) remains on owner, eligible background, and hourly repair paths; runtime-writer request paths and their deferred Document defaults never wait on it (the document-keep exception above remains synchronous). No new model calls.

### A2 — Receipts are per-field, on-row, STATE-bearing
One `pii_receipts` JSONField per model, keyed by field name (JSON-carrying fields aggregate placeholders per top-level field — chat receipts are offset-free, so nested text needs no offsets). Receipt schema = chat metadata + `state`: `placeholder` (confirmed clean) | `residual` (unminted spans recorded) | `unconfirmed` (`redaction-error` or request-path `detector-deferred`; known-values-scrubbed raw) | `bypass` (flag-off/disabled — no checked provenance ran; owner legacy mode may still redact unchecked). Absent key = pre-P3 legacy. State drives BOTH the repair sweep and the migration fence (A7). Flag-on content receipts come from either checked analysis or the explicit deterministic deferred path; `bypass` receipts carry no placeholder data.

**W2 receipt note:** W2 re-shapes receipts to placeholder-only (values resolved at owner-read) — value-bearing receipts undermine the encryption-ladder composition; ratified for W2, tolerated for W1c canary volume.

### A3 — Rehydrate at the owner boundary ONLY, via the serializer layer
Extend the live opt-in pattern (`document_serializers.py:10-24`, `lifecycle_serializers.py:10-32`, `_owner_ctx`): rehydration + metadata emission in serializers/response-builders keyed on explicit owner context; runtime serializers structurally never receive it. Fix owner surfaces that bypass it (Dashboard Horizons, owner memory view, journal-entry/review serializers). Read-path changes ship unconditionally (no-op on raw rows). Known paste-edge (review P2-6): legacy raw text containing a literal mapped token gets swapped on newly-rehydrating surfaces — pre-existing behavior on Document GET; receipts eventually disambiguate; accepted + documented.

### A4 — Flag: `layer1_placeholder_writes`, per-tenant, default False — PRE-P3-PRESERVING OFF
Flag-off preserves each path's PRE-P3 behavior: owner surfaces that redact today keep their legacy unchecked redaction (receipt `bypass`/`legacy-redact`); runtime/background stay pure passthrough. No NEW detection or minting is introduced anywhere by flag-off. Flag-on enables the full chokepoint per writer class. Reads/rehydration/search-translation ship unconditional. Canary → Kiho → fleet per the standing ladder. Flag shape mirrors `recall_capture_enabled` (actively checked + management command), not the dark `encrypt_journal_writes` shape.

### A5 — Search translation (variants, not tokens)
Per §1.5. W1c scope: Task/Goal owner `icontains` search (`lifecycle_views.py:271-274,314-317`). Document FTS websearch translation lands in W2 (plain-term variant union; no tsquery surgery in v1).

### A6 — Live violations fixed as named standalone items
- **W1a Siri egress** (`siri_views.py`): build the cloud-model request from placeholder-space state + entity legend (#1377 mechanism) AND redact the raw spoken intent chat-ingress-style before it enters the request; rehydrate only the final owner-facing response.
- **W1b Insights inverse-rehydration flip**: storage flips to placeholder-space (`_clean_assistant_text_for_app` deliberately rehydrates pre-storage today, `pending_queue.py:2638-2672`) **bound in the SAME PR to its owner read surfaces** (`_serialize_insight` returns raw `ins.statement`, `insights/views.py:233-247`; confirm/refute echoes; synthesis delivery) — flipping storage alone would show placeholders in the iOS insights UI that night (review P1-4). Mixed-space dedup residual (legacy real-name insights vs new placeholder insights degrade marker/synthesis matching across the boundary) — documented, accepted for v1.

### A7 — Migration (existing rows): designed now, run NEVER without MJ
Per-store command, fenced PER FIELD on receipt state — a field migrates unless `state=placeholder` (review P1-3: row-presence fencing breaks on bypass receipts, unconfirmed rows, and partial-JSON updates). Precondition per store: repair queue drained. Batching (review P2-7): pre-scan batch → mint all new entities in ONE per-tenant locked transaction → rewrite rows OUTSIDE the lock; off-peak; resumable; dry-run-first; canary-only until MJ fleet go. Ordering: migration precedes any `Document` encryption backfill (redact → encrypt; `enc_columns.py:19-23` exclusions stay deferred until this lands).

Runbook accounting note: runtime transition re-authoring performs incidental migration of touched rows; migration accounting must expect it.

### A8 — Explicitly out of scope / excluded
Chat pipeline (already placeholder-space) · friends sharing scrub (fail-closed, distinct contract) · **cross-tenant shared stores (SharedGoal/SharedUpdate/FriendMessage): EXCLUDED by design — creator-namespace placeholders are meaningless-or-wrong against the recipient's map; logged residual, never routed through the per-tenant chokepoint** (review P2-4c) · sautai EGRESS exception (prompt rehydration at client) — but `SautaiMealPlanJob.user_prompt` INGRESS storage is in-scope (W3) · `UserMemory` (dead model, no production writer; flagged for deletion) · OC workspace files (memory-sync stays known-only+no-mint) · iOS client work.

### A9 — Entity retirement becomes registry-aware (review P1-1)
New `apps/pii/store_registry.py`: each wave registers its placeholder-bearing surfaces `(model, flat fields, JSON paths, receipts field)`. Consumers:
- **Junk sweep** heal-before-delete fans out over the registry (today it heals only Document/Task/Goal/DocumentChunk flat fields, `junk_sweep.py:185-190` — correct semantics for junk: token → original value rewrite, then delete binding).
- **Owner explicit delete/bulk-delete** (`tenants/views.py:1446-1467,1537-1563` — currently deletes bindings with NO healing, admitting it breaks rehydration): switches to **tombstoning** — binding kept for rehydration, marked retired (hidden from registry UI, excluded from minting reuse and from egress known-values substitution decisions as appropriate). Healing-by-rehydration is WRONG for real entities (it would write real names back into stores — the inverse of this program). True purge of a tombstoned value = migration-grade rewrite over the registry; deferred, documented.
- **Repair sweep + migration** iterate the same registry. (Arbiter is safe as-is — stamps/denies, never deletes.)

Retirement auto-denies the value only when no other active binding shares the canonical name. Retired bindings are excluded from egress substitution and legends; rehydration retains them.

**W2b memory-editor exception:** an owner surface whose rendered text comes straight back as a write (today: the memory editor, `journal/views.py` `MemoryView`) rehydrates ACTIVE bindings ONLY — a retired placeholder stays a literal token. Rehydrating it there would re-author the real name on save with no substitution available (retirement removed the value from the known-value path), so owner-deleting an entity would be the one action that writes it back in plaintext. The token round-trips byte-for-byte instead, and still rehydrates on every read-only surface.

### A10 — Repair sweep (buildable spec)
QStash-scheduled (hourly), per-tenant batch over registry stores where any field state ∈ {`unconfirmed`, `residual`}; re-runs `author_text` with current map + full NER; idempotent via receipt state transition; bounded batch size; DLQ + counter telemetry; drain-required before migration (A7). Reuses the transcripts alert mechanism (steward-gated, metadata-only). The live schedule is offset to minute `:13` so it does not collide with top-of-hour tenant crons. One pass is hard-capped at 16 rows and 16 checked texts (at most 32 detector passes), with at most four rows/texts and four inspected tenants per tick. Hourly tenant/store rotation prevents low-ID/early-store starvation; recursive JSON persists a keyed, resumable leaf cursor without advancing fruitless-attempt counts until the full field completes. Slow NER runs before a short compare-and-swap row lock, so a concurrent request write wins instead of being overwritten.

Live-write failure-rate alerting (not just repair-time) lands with W2.
