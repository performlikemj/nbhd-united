# Glossary — NBHD United domain & platform terms

Shared vocabulary for the codebase. Terms are grouped; **bold** cross-references point to other entries. For deeper treatment see [`docs/agents/architecture.md`](agents/architecture.md), [`docs/agents/invariants.md`](agents/invariants.md), and the reference set under [`docs/reference/`](reference/).

## Product & tenancy

| Term | Meaning |
|---|---|
| **NBHD United** | The multi-tenant SaaS platform. This repo is its **control plane** (Django) + subscriber **console** (Next.js). |
| **Tenant** | One paying subscriber. Each tenant gets a private AI assistant running in its own isolated container. Identified by a UUID; most per-tenant data is scoped by a `tenant` FK and protected by **RLS**. |
| **Tenant prefix** | The first segment of a tenant UUID (e.g. `148ccf1c-ef13-47f8-a`) used to name that tenant's Azure resources. |
| **Control plane** | The always-on Django app (`nbhd-django-westus2`) that owns identity, billing, routing, provisioning, and cron. It orchestrates the per-tenant containers but is not itself a tenant runtime. |
| **Console** | The subscriber-facing dashboard — the Next.js web app and the iOS app, both talking to the same DRF API. |
| **Pillar** | A product feature area surfaced in the console and to the assistant: **Core**, **Fuel**, **Journal**, **Horizons**, **Insights**, **Finance**, **Friends/Neighborhood**, **Constellation**. Each maps to a Django app. |

## AI runtime (OpenClaw)

| Term | Meaning |
|---|---|
| **OpenClaw** | The AI assistant runtime — a separate container image (`Dockerfile.openclaw`, `nbhd-openclaw:<ocver>-<shortsha>`) that runs one tenant's assistant. Reached over HTTP by the control plane; it runs a conversational turn and calls tools. |
| **`oc-*` container** | A tenant's Azure Container App running OpenClaw, named `oc-<tenant_prefix>`. One per active tenant. |
| **Workspace / File Share** | The Azure File Share (`ws-<tenant_prefix>`) mounted into the `oc-*` container holding the tenant's runtime files: `AGENTS.md`, `USER.md`, `memory/`, config. |
| **`AGENTS.md`** | The assistant's persona + per-tenant gates/instructions, generated by Django and pushed to the workspace. Must survive container restarts. |
| **`USER.md`** | The per-user "envelope" (profile/context) written between `BEGIN`/`END` sentinels, generated by Django and pushed through the **sanitize chokepoint**. |
| **`openclaw.json`** | The per-tenant OpenClaw config, generated by `apps/orchestrator/config_generator.py`. OpenClaw **live-reloads** it — hence "image before config". |
| **Bump** | Rolling out a new image or config to tenants. `bump_all_tenant_images` = image only; `bump_openclaw_version --all` = version + config. A pending config marked in DB is applied by `apply_pending_configs` / the CI post-deploy step. |
| **Image before config** | Invariant: never push a config that needs a newer image than what's deployed. OpenClaw live-reload would otherwise roll back to last-good config. |
| **Tool policy** | The deny-list of OpenClaw tools (`apps/orchestrator/tool_policy.py`) — e.g. built-in `memory_search` is denied because it puts **SQLite on the share** (see invariant #1). |
| **Action gating** | The approve/deny flow (`apps/actions`) where a sensitive assistant tool call is held until the user confirms it via a button callback. |
| **LiteLLM** | Model-routing layer OpenClaw uses to reach LLM providers. |
| **OpenRouter** | The default platform LLM gateway. Platform key at Key Vault `openrouter-api-key`; **ZDR** enabled for platform traffic (not BYO). |
| **ZDR** | Zero Data Retention — provider setting so prompts/completions aren't retained. Enabled for platform OpenRouter traffic only. |
| **BYO / BYOK** | Bring-Your-Own-Key: a tenant supplies their own LLM provider credentials (`apps/byo_models`), used instead of the platform key. |

## Lifecycle & scheduling

| Term | Meaning |
|---|---|
| **Provisioning** | Creating a tenant's container + file share + managed identity (`apps/orchestrator`). Driven by billing on subscription start. |
| **Hibernation** | Idle tenants (no message ≥2h) have their container revision **deactivated** (not scaled to zero). `runningStatus: Running` is therefore a false signal — trust the Replicas metric. |
| **Wake** | Bringing a hibernated tenant back on an inbound message. `wake_hibernated_tenant` also **self-heals** the image to the fleet tag if drifted. |
| **Single-revision mode** | Telegram containers run one revision only, to prevent 409 poller conflicts from multiple pollers. |
| **QStash** | Upstash's HTTP scheduler — the project's cron mechanism (`apps/cron`). **Not Celery** — never add `django_celery_beat`. Dedup-ids may not contain `:` or whitespace. |
| **Drain** | Forwarding queued `PendingMessage`s to a tenant container; triggers a **wake** if hibernated. |
| **Dedup gate** | `apps/router/inbound_dedup.py::claim_inbound_event` — every inbound handler claims the event before side effects, because LINE/Telegram redeliver. |
| **Sanitize chokepoint** | `apps/orchestrator/azure_client.py::_put_share_file` — all File Share text writes strip null + C0 control bytes. Never hand-roll a share upload. |

## Data & isolation

| Term | Meaning |
|---|---|
| **RLS** | PostgreSQL Row-Level Security. The load-bearing tenant-isolation backstop: Django connects as a **non-BYPASSRLS** role so per-tenant policies actually apply. |
| **`app_user`** | The Postgres role Django uses via the transaction-mode pooler. Non-BYPASSRLS, so RLS predicates are enforced. Has a 60s `idle_in_transaction_session_timeout`. |
| **RLS GUC** | The session variable the RLS predicate keys off. Set per-request from the authenticated tenant (`set_rls_context`); re-set after a connection reset in long tasks. |
| **FORCE RLS** | Stronger RLS applied to the **Friends/Neighborhood** tables so policies apply even to the table owner — the one place tenant data legitimately crosses the tenant boundary. |
| **Service-role** | A marked connection mode (`set_rls_context(service_role=True)`) used by control-plane paths that must satisfy FORCE-RLS policies while acting across tenants. |
| **PII redaction** | `apps/pii` — inbound user text has PII replaced with **placeholders** before it reaches the LLM; outbound text is **rehydrated**. |
| **RedactionSession** | The per-conversation mapping of placeholder ↔ real value that makes redaction reversible and stable. Same name → one stable placeholder per tenant. |
| **Rehydration** | Replacing placeholders with the real values on the way back out to the user. |
| **`nbhd_journal_search`** | The Postgres-backed search path journal uses instead of OpenClaw's SQLite `memory_search` (which is banned from the share). |

## Infrastructure & delivery

| Term | Meaning |
|---|---|
| **Managed Identity** | Azure identity `mi-nbhd-<tenant_prefix>` a container uses to read **Key Vault** secrets. Key Vault `identityref:` uses the `mi-nbhd-` name, **not** the `oc-` container name. |
| **Key Vault** | `kv-nbhd-prod` — secret store. Secrets never printed to conversation; rotation via the `/rotate-keys` skill. |
| **ACR** | Azure Container Registry `nbhdunited.azurecr.io`. A nightly purge task keeps it lean. |
| **Static Web App** | Azure hosting for the frontend static export (`nbhd-united-frontend`). No SSR. |
| **dj-stripe** | Django library mirroring Stripe objects into the DB; billing webhooks land at `/stripe/`. |
| **Constellation** | The gamified/visual layer of the console (galaxy/orb UI). |
| **Horizons** | A goals/purpose pillar; DB-backed, calls OpenRouter directly, works even while a tenant is hibernated. |
