## Facts (verified in prod + code)
- One Django container runs `poll_telegram` + gunicorn (2 `gthread` workers × 8 threads, no `--preload`, recycle ~1,000 req) from `startup.sh:13-15`; each worker loads the DeBERTa model AFTER fork in `post_worker_init` (`gunicorn.conf.py:8-37`); the poller lazily loads a THIRD copy on its first redaction. Measured: worker RSS 1031/753 MB with PSS≈RSS (no sharing), poller 234 MB pre-load; box 2.9/4 GB.
- Engine is a per-process lazy singleton (`apps/pii/engine.py`, `liquid_engine.py`); selection `PII_DETECTOR_ENGINE=deberta|liquid` (`apps/pii/config.py`). Fail-open today: a neural pipeline exception ⇒ `model_results=[]`, Presidio pattern recognizers still run, known-entity substitution already happened (`redactor.py` ~1886-1895). QStash tasks run inside gunicorn workers; LINE/iOS redaction too. No Celery.
- Liquid eval (docs/pii-detector-eval-2026-08-15.md): +1,207 MiB RSS vs +445 MiB, 49.5 ms vs 21.2 ms median; recall 62→80 % (JA 24→60 %). Its `score=1.0` is an acceptance marker, not confidence. #695 was an ONNX/Optimum Linux-vs-macOS incident, not proof Liquid is nondeterministic. The serving image contains DeBERTa only; `INCLUDE_LIQUID=true` build path exists (`Dockerfile:33-`).
- `--preload` alone would not help (load happens post-fork); moving the load pre-fork risks torch fork hazards and still would not cover the poller. Safetensors mmap sharing: unconfirmed and contradicted by PSS≈RSS.

## Decisions
D1 **Two flags, not one:** `PII_DETECTOR_TRANSPORT=local|shared` (new, default `local` = today) × `PII_DETECTOR_ENGINE=deberta|liquid` (existing). Rollback of either axis is one env flip. Both are container-wide (single-revision app), never per-tenant.
D2 **Server** `apps/pii/shared_server.py` (stdlib only): Unix socket `/run/nbhd/pii-detector.sock` (dir 0700, socket 0600, same UID; no TCP). Length-prefixed JSON frames; request `{"text": …}`; response `{"spans": [{"entity_group","score","start","end"}], "engine": …}` — nothing else. ONE inference thread (`max_workers=1`) with a bounded queue (32); tokenizer parallelism off; torch intra/inter-op threads = 1; deterministic algorithms on; loads exactly one model chosen by `PII_DETECTOR_ENGINE`. Readiness = a ping frame answered after the model is warm. `startup.sh`: start the server after migrations/config bump and BEFORE the poller and gunicorn; wait ≤ 180 s for readiness, then start the app processes anyway (they fail open until ready); supervise: restart a dead server with capped backoff while clients fail open. `/health/` stays model-independent.
D3 **Client** `SharedPiiPipeline` returned by `get_pii_pipeline()` when transport=shared; `_detect_pii` unchanged. 2 s end-to-end deadline; circuit breaker: 3 consecutive transport/protocol failures → open 30 s → one half-open probe. Every failure (timeout, refused, protocol, invalid span: non-finite score, `start<0`, `end>len`, `start>=end`, frame/span caps) raises the SAME internal error class the existing catch handles ⇒ Presidio-only, byte-identical to today's fail-open. Client processes NEVER import or load a local neural model (test asserts it). Presidio stays in every client process.
D4 **Telemetry (shape-only):** client JSON log event `pii_detector_client` {engine, transport, outcome ∈ ok|timeout|connect|protocol|circuit_open, latency_ms, len_bucket, span_count}; server event {engine, queue_ms, inference_ms, total_ms, len_bucket, span_count, queue_depth}. Never text. KQL in the proposal (§D) is the dashboard.
D5 **Step 2 — Liquid:** separate PR after step 1 is measured. Dual-model image via `INCLUDE_LIQUID=true` (both artifacts on disk, one in RAM). New `python -m apps.pii.span_manifest --corpus golden+eval` emitting sorted raw + final spans; acceptance = ZERO diff between macOS and the `linux/amd64` image at the pinned revision with 1 torch thread + deterministic algorithms. `score=1.0` must not bypass label mapping, structured validation, hygiene, `MINT_VALIDATED`/`MINT_NEVER`. Rollback `liquid → deberta`.
D6 **Rollout + measurement:** PR1 ships with transport=local (no behaviour change) → deploy → flip `shared+deberta` in one revision → force one Telegram + one HTTP/iOS + one LINE redaction → probe (`/proc/*/smaps_rollup` Rss/Pss for gunicorn, poll_telegram, shared_server; peak cgroup memory) + KQL p50/p95/timeouts/fallbacks + `PII_DETECTOR_ENGINE=deberta python -m apps.pii.golden_check` + `scripts/eval_pii_detectors.py` → PR2 dual artifact → flip liquid → same probes → default only with headroom + p95 acceptable.
D7 **Stop conditions:** summed PSS not materially lower after step 1; shared Liquid leaves < ~800 MB headroom under the 4 GB cgroup during worker long-tail growth; the one-worker queue breaks p95 such that replicas erase the saving; span manifest differs across platforms; clients can silently load local models.
