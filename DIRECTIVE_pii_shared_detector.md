## Facts
- One Django container runs `poll_telegram` (`startup.sh:13-15`) + gunicorn (`startup.sh:36-47`: 2 `gthread` workers × 8 threads, no `--preload`, `--max-requests 1000`); the PID-1 shell supervises both under `set -e` (`startup.sh:2`, loop `startup.sh:53-71`). Each worker loads DeBERTa AFTER fork in `post_worker_init` (`gunicorn.conf.py:8-37`, unconditional `get_pii_pipeline()`); the poller lazily loads a THIRD copy on its first redaction. **Owner-supplied prod measurement** (rev 0001306, `/proc` probe, not reproducible from the repo): worker RSS 1031/753 MB with PSS≈RSS (no sharing), poller 234 MB pre-load; box 2.9/4 GB.
- Engine = per-process lazy singleton (`apps/pii/engine.py:88-145`); selection `PII_DETECTOR_ENGINE=deberta|liquid` (`apps/pii/config.py:14-23`, `engine.py:134-145`). **Neural fail-open today = `redactor.py:1967-1971`**: bare `except Exception: model_results = []`; Presidio recognizers still run; known-entity substitution already happened. Consequence (critique #1): `redact_user_message_checked` (`redactor.py:1500-1526`) still returns `confirmed=True`, and `_residual_summary` (`authoring.py:171-209`) returns `count=0`, when the neural model never ran — a receipt that reads clean while neural-only PII (IDs, passwords, accounts, IPs, DOBs) is raw. This bug exists TODAY (a worker whose model failed to load confirms everything); the sidecar adds a new way to hit it (socket down / warming).
- Overlap dedup keeps the higher score, ties → shorter span (`redactor.py:2338-2366`); Liquid emits `score=1.0` for every span (`liquid_engine.py:42-54`), so a broad Liquid PERSON would beat a validated Presidio email/phone (critique #11).
- Deploy: `ci-cd.yml:53` hardcodes `PII_DETECTOR_ENGINE: deberta`, `ci-cd.yml:635-642` passes it to `config/containerapp_deploy.py` (`--pii-detector-engine`, lines 84-101) which writes the env on EVERY deploy; readiness probe = 48 × 5 s on `/health/` (`containerapp_deploy.py:19-34`). No transport var exists → a manual flip is reverted by the next deploy (critique #14). Single-revision app (poller 409 avoidance, `ci-cd.yml:55-64`) ⇒ no multi-revision canary.
- Image: `Dockerfile:41-44` copies the DeBERTa-only immutable tag `pii-model:deberta-only-a038061af92047b0` (two-place rule with `ci-cd.yml:473`); `INCLUDE_LIQUID` lives in `Dockerfile.pii-model:35-43`; the serving-image smoke (`ci-cd.yml:497-505`) asserts `/app/pii-model/liquid` is ABSENT. No `USER` in the image → gunicorn, poller and sidecar all run as the same UID (socket modes = containment, not privilege separation).
- Liquid eval (`docs/pii-detector-eval-2026-08-15.md:54-61`): +1,207 MiB RSS vs +445 MiB, 49.5 ms vs 21.2 ms **sentence-level medians only** (no p95, no long inputs); recall 62→80 % (JA 24→60 %). Inputs reach 8k chars (iOS, `chat_views.py:63-75`), 10k (Telegram document, `poller.py:1411-1416`), 20k (Gmail body, `google_api.py:267-269`).
- `--preload` alone would not help (load is post-fork); a pre-fork load could remove one gunicorn copy but cannot share with the poller and cannot reach the one-copy Liquid outcome — **declined** (critique #17), not experimented.

## Decisions
D1 **Two flags, durable in the deploy path.** `PII_DETECTOR_TRANSPORT=local|shared` (new, default `local` = today) × `PII_DETECTOR_ENGINE=deberta|liquid` (existing). Both container-wide, never per-tenant. Source of truth = the `env:` block of `.github/workflows/ci-cd.yml` (add `PII_DETECTOR_TRANSPORT: local`), passed as `--pii-detector-transport` to `config/containerapp_deploy.py`, which writes BOTH env vars on every deploy (test asserts both). **The flip is a one-line PR** to that block (single-revision app ⇒ a flip needs a new revision anyway); **rollback = revert PR** (owner Fable, target < 15 min) with the emergency lever `az containerapp update -n <ACA_APP> -g <RG> --set-env-vars PII_DETECTOR_TRANSPORT=local` used only to stop the bleeding before the revert lands.
D2 **Server** `apps/pii/shared_server.py`, run as `python -m apps.pii.shared_server` (stdlib + the existing engine loader; must never open a DB connection). Unix socket path from `PII_SHARED_SOCKET` (default `/run/nbhd/pii-detector.sock`); the server creates the dir 0700 and the socket under `umask 077`, removes a stale socket file before bind. **Protocol v1, one connection per call** (connect → one request frame → one response frame → close; no request IDs, no pipelining): frame = 4-byte big-endian length + UTF-8 JSON. Request `{"v":1,"engine":"deberta","text":"…","ttl_ms":N}`; ping `{"v":1,"ping":true}` → `{"v":1,"ready":bool,"engine":"…","protocol":1}`. Success `{"v":1,"engine":"…","spans":[{"entity_group","score","start","end"}]}`; error `{"v":1,"error":"queue_full|expired|engine_mismatch|bad_request|too_large|not_ready|inference_failed"}`. Server rejects `v≠1`, `engine≠configured`, request frame > 1 MiB, missing/invalid fields — before queueing. ONE inference thread; bounded FIFO queue (`PII_SHARED_QUEUE_MAX`, default 64) with fast `queue_full` rejection; each job carries an absolute deadline from `ttl_ms` and is dropped (`expired`) if it is past due when dequeued, or if the client disconnected. `TOKENIZERS_PARALLELISM=false`, `torch.set_num_threads(1)`, inter-op 1, `torch.use_deterministic_algorithms(True)`; loads exactly one model chosen by `PII_DETECTOR_ENGINE`. Response spans ≤ 4096, response frame ≤ 1 MiB. Logs: shape-only (D6); **never the text, never `str(exc)` of a decode error — exception class names only**.
D3 **Client** `apps/pii/shared_client.py`: `SharedPiiPipeline` (callable `(text) -> list[dict]`), returned by `engine.get_pii_pipeline()` when transport=shared — `_detect_pii` unchanged at the call site. One deadline covers connect + queue + inference + framing: `PII_SHARED_DEADLINE_S` (default **5.0** until D7 measurement sets it; `ttl_ms` sent = remaining budget). Circuit breaker: 3 consecutive transport/protocol failures → open 30 s → one half-open probe. Class `SharedPiiError(Exception)` for EVERY failure (timeout, refused, `not_ready`, error frames, protocol version/engine mismatch, oversized/truncated frame, malformed JSON, invalid span: non-finite score or outside [0,1], `start<0`, `end>len(text)`, `start>=end`, wrong keys/types, > 4096 spans). The client fully materializes and validates the whole response BEFORE returning, so nothing can raise during the caller's later iteration (critique #2). Client processes never import `transformers`/`torch`/`liquid_engine` (test asserts via a subprocess with those modules blocked). Presidio stays in every client process.
D4 **Receipts must not confirm what the model never checked (critique #1 — blocker).** Smallest mechanism: `redactor.py` keeps a `threading.local()` neural-outcome record set inside `_detect_pii` (`available=True` after a successful pipeline call, `False` in the existing `except` at 1970); `redact_user_message_checked` resets it before `_redact_user_message` and, if it reads `False` afterwards, returns `RedactionOutcome(text=<the Presidio-redacted text>, confirmed=False, reason="neural-unavailable")` — **text parity with today's fail-open is preserved; only the receipt changes**. `_residual_summary` resets it too and raises `NeuralDetectorUnavailable` when it reads `False`; `authoring.py:517-531` catches that class first and writes `state="unconfirmed", reason="neural-unavailable"` (the existing known-values fallback still runs). Applies to BOTH transports (it fixes today's load-failure case as well). **Callers of the checked API are NOT changed in PR1** — the handback documents what each caller (`poller.py:1595-1618`, `line_webhook.py:1446`, `chat_views.py:754`, `views.py:80/108`, `chat_views.py:153/185`) does with `confirmed=False` so Fable/MJ can decide whether hold/queue semantics need work (separate lane).
D5 **Startup + supervision (critique #3 blocker, #4, #5).** `startup.sh`: after migrations/config bump, start the sidecar (transport=shared only), then the poller, then gunicorn — **no shell-level readiness wait at all**; gunicorn binds :8000 immediately as today. `gunicorn.conf.py::post_worker_init` gets an explicit branch: transport=shared → NO detector construction; poll the sidecar ping up to `PII_SHARED_WARM_WAIT_S` (default 90 s, i.e. ≤ today's measured 8-114 s in-process warm) then proceed either way, logging `post_worker_init: PII shared transport ready in N s` or `… not ready after N s; failing open (unconfirmed receipts) until ready`. Supervisor: `set -e`-safe (`wait -n … || rc=$?` idiom, never a bare `wait -n` under `set -e`), three children, restarts a dead sidecar with backoff 5 s → 60 s cap (both during warm-up and steady state), restarts the poller as today, exits on gunicorn death, trap kills all children on SIGTERM/SIGINT, stale socket removed before each sidecar (re)start. Tested by `scripts/test_startup_supervisor.sh` running `startup.sh` with `NBHD_STARTUP_FAKE=1` (fake commands via env: sidecar dies → restarted; gunicorn dies → exit code propagated; SIGTERM → all children gone, no orphans). `/health/` stays model-independent. Gunicorn `--max-requests` recycling stays (critique #9: it bounds non-model long-tail growth).
D6 **Telemetry (shape-only):** client log event `pii_detector_client` {engine, transport, outcome ∈ ok|timeout|connect|not_ready|queue_full|expired|protocol|engine_mismatch|bad_response|circuit_open, latency_ms, len_bucket, span_count}; server event `pii_detector_server` {engine, outcome, queue_ms, inference_ms, total_ms, len_bucket, span_count, queue_depth} + a readiness line with warm seconds. Never text, never payload reprs. KQL from the proposal §D is the dashboard.
D7 **Measure before choosing numbers (critique #6, #7, #9, #12).** Under `PII_REAL_MODEL_TESTS=1` (S5): (a) **parity** — golden + eval corpus through the local DeBERTa pipeline and through the shared client against a real server subprocess: raw spans AND `_detect_pii` output identical; (b) **latency** — p50/p95/p99 for 200-char, 8k, 10k and 20k worst-case (4-byte UTF-8) inputs, sequential and in a 24-thread burst (16 gunicorn threads + poller background threads + LINE double-call); (c) **soak** — 2,000 alternating 200-char/20k calls, server RSS/PSS high-water sampled every 100 calls; acceptance = growth over the last 25 % of calls < 5 % (plateau). Numbers land in the handback + `docs/`; **Fable sets the final `PII_SHARED_DEADLINE_S` / `PII_SHARED_QUEUE_MAX` defaults from (b) before the flip PR** (deadline ≥ 3 × burst p99 for 20k). No plateau ⇒ add a sidecar `--max-calls` recycle in the flip PR (supervisor already restarts it).
D8 **Step 2 — Liquid (PR2)**, only after step 1 is measured in prod. **L0 first (critique #11 blocker): source-aware overlap precedence** — a validated structured span (Presidio email/phone/card/IBAN) beats any overlapping neural span regardless of score; Liquid's `1.0` is never compared against Presidio scores; tests: Liquid PERSON@1.0 overlapping an email → email wins; DeBERTa unchanged on the golden set. L1 dual-model artifact: fences EXPAND to `Dockerfile`, `Dockerfile.pii-model`, `ci-cd.yml` (build with `INCLUDE_LIQUID=true`, mint a NEW immutable tag, update the two-place rule, REVERSE the `/app/pii-model/liquid` absence assertion); record compressed size, first-build time, revision pull time. L2 `python -m apps.pii.span_manifest --corpus golden+eval` (sorted raw + final spans) with ZERO diff macOS vs `linux/amd64` at the pinned revision — a determinism smoke, not acceptance; acceptance = D7(a) parity re-run with Liquid + D7(b)(c) numbers. `score=1.0` must not bypass label mapping, structured validation, hygiene, `MINT_VALIDATED`/`MINT_NEVER`. Rollback `liquid → deberta` via the flip-PR mechanism.
D9 **Rollout + first-hour gates (critique #15).** PR1 ships transport=local (no behaviour change except D4 receipts) → deploy → D7 numbers → **flip PR** (`PII_DETECTOR_TRANSPORT: shared`, MJ informed first) → force one Telegram + one HTTP/iOS + one LINE redaction → first hour: KQL `pii_detector_client` outcome≠ok < 1 %, `queue_full`+`expired` = 0, sidecar restarts = 0, worker/container restarts = 0, p99 < deadline/2, `/proc/*/smaps_rollup` Rss/Pss for gunicorn, poller, sidecar + cgroup peak (headroom ≥ 800 MB), `PII_DETECTOR_ENGINE=deberta python -m apps.pii.golden_check` inside the deployed image, synthetic leak probe (send a known neural-only PII string through each channel; receipt confirmed + placeholder present). No multi-revision canary (poller duplication) — the flip PR plus these gates IS the canary; revert PR is the rollback.
D10 **Stop conditions:** summed PSS not materially lower after step 1; shared Liquid leaves < ~800 MB headroom under the 4 GB cgroup during worker long-tail growth; the one-thread queue breaks p95 such that replicas erase the saving; soak shows no plateau and a recycle policy does not fix it; span manifest differs across platforms; clients can load local models; D4 turns a transient warm-up into user-visible message loss (then the caller-semantics lane goes first).
